# Taste
- Wants the assistant to take full ownership of layout and UI/UX ("i want u handle the layout and ui ux all") — decide the design direction and apply it across all surfaces rather than implementing piecemeal or asking for decisions. Confidence: 0.9
- Prefers the sona-ui aesthetic (https://github.com/Dinil-Thilakarathne/sona-ui): dark neutral canvas (neutral-900/950), glassy floating surfaces with backdrop blur, cyan accent for interactive/active states, soft shadows, rounded-xl/2xl corners, spring-animated drawer layouts, and mono micro-labels with uppercase tracking. Confidence: 0.85
- Keeps the reference project's native palette intact when cloning it: when asked to clone a design (e.g. sona-ui), the docs/clone surface keeps the source project's own Tailwind palette (`neutral-*` + `dark:`) as a distinct visual layer — parallel to how other surfaces have their own token layers — rather than migrating it to the project's own CSS tokens. Confidence: 0.75
- Favors a "clone a reference project to make it better" workflow: use an existing UI library/design as the source of truth, restyle the product to match, and improve on it — rather than inventing a new design language from scratch. Confidence: 0.8
- Communicates informally with shorthand and typos ("pls", "u", "i want", "like i do", "cntinue the fixla"); keep responses practical and direct, avoid over-formalizing. Repeatedly sends terse one-liners ("continue your work", "check?", "check again") instead of full sentences. Confidence: 0.9
- When wrapping up UI work, wants concrete local URLs/links to view the result ("where show me link on local") — lead with the exact localhost links (and how to get the servers running if needed) rather than just a written summary. Confidence: 0.7
- When the user asks to view the app ("pls open the localhost to me to view more"), actually start/restart the local dev servers (web on :3000, API on :3001, Postgres up) so it's viewable — including killing stale dev servers that serve old builds — then verify the key routes respond (200) and hand back the concrete localhost URLs. Confidence: 0.8
- Prefers a plan-first-then-execute workflow for layout/UI tasks: first produce a detailed, self-contained plan/spec (full component/prop/layout details), then — once approved or when told to execute ("now pls execute from all my plans above", "execute it to me base on docs/design/") — implement it fully rather than stopping at planning or deferring execution to another model. Confidence: 0.85
- Treats the written design docs (`docs/design/`) as the authoritative spec to implement from — when a layout is documented, the build should be executed directly "base on docs/design/" rather than re-deriving from source code or improvising. Confidence: 0.7
- Communicates in mixed Vietnamese/English; comfortable with the assistant understanding and responding to Vietnamese phrasing. Confidence: 0.8
- Reports UI bugs by sending a screenshot with a terse pointer at the problem (e.g. "cntinue the fixla [screenshot] cai layout mau do do chua cia gi?") — the screenshot is the source of truth; use vision to inspect it and fix what's shown rather than asking for clarification. Confidence: 0.9
- Holds an exacting visual-QA standard: anything that visually appears broken on screen (dark empty blocks, stray borders, off-screen elements painting through) is a bug to fix, even when the underlying logic (e.g. `aria-hidden`/`inert`) is technically correct. Confidence: 0.85
- Prefers minimal interruption: gets frustrated when work is blocked on prompts/shortcuts that don't do what they say (e.g. "cu hien ctrl + a ma toi bam hoai ko duoc") and wants the assistant to proceed without asking for per-edit approval (auto-accept permission mode) rather than stopping to ask each time. Confidence: 0.8
- When the user says "continue" / reports they cannot approve a plan (e.g. Mac shortcut broken: "can not accept the plan with my keyrows or short cut not working on mac so pls continue the plans"), execute the already-presented plan end-to-end immediately without re-prompting for approval — stopping again only adds friction. Confidence: 0.85
